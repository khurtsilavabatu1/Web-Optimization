# ლექცია 3 — გამოსახულების და ფონტების ოპტიმიზაცია

## 3.1 გამოსახულების ოპტიმიზაცია

### რატომ არის მნიშვნელოვანი?
- სურათები ტიპიურად **50-70%** შეადგენს ვებგვერდის მთლიანი წონისას
- არაოპტიმიზირებული სურათი: 2-5MB, ოპტიმიზირებული: 50-200KB

### ფორმატების შედარება:

- **JPEG** — გამოყენება: ფოტოები, ზომა: საშუალო, ხარისხი: კარგი, მხარდაჭერა: ყველა
- **PNG** — გამოყენება: გამჭვირვალე, ტექსტი, ზომა: დიდი, ხარისხი: ძალიან კარგი, მხარდაჭერა: ყველა
- **WebP** — გამოყენება: ყველაფერი, ზომა: მცირე (-25-35%), ხარისხი: ძალიან კარგი, მხარდაჭერა: 97%+
- **AVIF** — გამოყენება: ყველაფერი, ზომა: ყველაზე მცირე (-50%), ხარისხი: საუკეთესო, მხარდაჭერა: 92%+
- **SVG** — გამოყენება: იკონები, ილუსტრაციები, ზომა: ძალიან მცირე, ხარისხი: სკალირებადი, მხარდაჭერა: ყველა

> **მხარდაჭერა** = რომელ ბრაუზერებში მუშაობს ფორმატი. "ყველა" ნიშნავს Chrome, Firefox, Safari, Edge ყველა ვერსიაში. 97%+ ნიშნავს, რომ ზოგიერთმა ძველმა ბრაუზერმა შეიძლება ვერ გახსნას.
>
> **სკალირებადი (SVG)** = ნებისმიერ ზომაზე გადიდდება ან შემცირდება ხარისხის დაკარგვის გარეშე, რადგან ვექტორული ფორმატია — მათემატიკური ფორმულებით აღწერს გამოსახულებას, არა პიქსელებით.
>
> **რატომ არის WebP/AVIF უფრო პატარა ზომის, მაგრამ იგივე ხარისხის?** განსხვავება არის კომპრესიის ალგორითმში. ახალი ფორმატები უფრო ეფექტურ ალგორითმებს იყენებენ — მაგალითად, უკეთ ხვდებიან სურათის რომელი ნაწილი ადამიანის თვალისთვის შეუმჩნეველია და იქ ზოგავენ მეტ ადგილს. JPEG 1992 წელს შეიქმნა და ძველი ტექნოლოგიით მუშაობს.

### HTML-ში ოპტიმალური სურათი:
```html
<!-- picture ელემენტით — ბრაუზერი აირჩევს საუკეთესოს -->
<!-- "საუკეთესო" = პირველი ფორმატი, რომელსაც ბრაუზერი მხარს უჭერს.
     ბრაუზერი source ელემენტებს ზემოდან ქვემოთ ამოწმებს:
     1. ჯერ ცდის AVIF-ს (ყველაზე მცირე ზომა)
     2. თუ AVIF არ იცის, ცდის WebP-ს
     3. თუ არცერთი არ იცის, იყენებს JPEG-ს (img — უნივერსალური fallback) -->
<picture>
  <source srcset="photo.avif" type="image/avif">
  <source srcset="photo.webp" type="image/webp">
  <img src="photo.jpg" alt="აღწერა" width="800" height="600" loading="lazy">
</picture>
```

### Lazy Loading:
```html
<!-- Native lazy loading -->
<img src="photo.jpg" alt="..." loading="lazy" width="400" height="300">

<!-- Above the fold — არ გამოიყენოთ lazy! -->
<img src="hero.jpg" alt="..." loading="eager" fetchpriority="high">
```

> **`loading="lazy"`** — სურათი იტვირთება მხოლოდ როცა მომხმარებელი მასთან ახლოს დასქროლავს. გამოიყენება ეკრანის ქვემოთ მყოფი სურათებისთვის.
>
> **`fetchpriority="high"`** — ბრაუზერს ეუბნები, ეს სურათი პრიორიტეტულია და პირველ რიგში ჩამოტვირთე. ბრაუზერი ნეტვორკის სიმძლავრეს ანაწილებს რესურსებს შორის და სურათები ჩვეულებრივ დაბალ პრიორიტეტზეა — ეს ატრიბუტი მას რიგში წინ წამოწევს, სხვა დაბალი პრიორიტეტის რესურსების ხარჯზე.

### Responsive Images:
```html
<img 
  srcset="image-400w.jpg 400w, image-800w.jpg 800w, image-1200w.jpg 1200w"
  sizes="(max-width: 600px) 100vw, (max-width: 1024px) 50vw, 33vw"
  src="image-800w.jpg"
  alt="აღწერა"
>
```

> **როგორ მუშაობს:** ერთი სურათის სხვადასხვა ზომის ვერსიები გვაქვს (400px, 800px, 1200px). `srcset`-ით ვეუბნებით რა ვერსიები არსებობს, `sizes`-ით — ეკრანზე რამდენ ადგილს დაიკავებს სურათი. ბრაუზერი თავად ირჩევს ოპტიმალურ ვერსიას. მაგალითად, ტელეფონი (400px ეკრანი, 100vw) ჩამოტვირთავს 400w ვერსიას, დესკტოპი (1920px, 33vw ≈ 640px) — 800w ვერსიას.
>
> **სურათების ვერსიები** ან ლოკალურად უნდა გქონდეს პროექტში (`/images/image-400w.jpg`), ან რემოუთ სერვერზე სრული URL-ით (`https://cdn.example.com/image-400w.jpg`). ორივე შემთხვევაში ყველა ზომის ვერსია რეალურად უნდა არსებობდეს — ბრაუზერი თავისით არ დააპატარავებს.

### React-ში (Next.js Image):
```jsx
import Image from 'next/image';

<Image src="/hero.jpg" alt="Hero" width={1200} height={600} priority />
<Image src="/photo.jpg" alt="Photo" sizes="(max-width: 768px) 100vw, 50vw" fill style={{ objectFit: 'cover' }} />
```

> **რას აკეთებს:** Next.js-ის `<Image>` კომპონენტი ავტომატურად აკეთებს იმას, რაც ჩვეულებრივ HTML-ში ხელით უნდა გაკეთდეს — ერთი ორიგინალი სურათიდან აგენერირებს სხვადასხვა ზომის ვერსიებს, აკონვერტებს WebP/AVIF ფორმატში და ამატებს `srcset`-ს. `priority` არის `fetchpriority="high"`-ის ექვივალენტი.

### ინსტრუმენტები:
- **Squoosh** (squoosh.app) — ონლაინ, ფორმატების შედარება
- **sharp** — Node.js ბიბლიოთეკა (build pipeline-ში)
- **Cloudinary / imgix** — CDN-based, on-the-fly optimization

> **Squoosh** — ვებსაიტი, სადაც ერთეულ სურათს ატვირთავ, თვალით ადარებ ფორმატებს და ოპტიმიზირებულს გადმოწერ. **sharp** — Node.js ბიბლიოთეკა, რომელიც კოდიდან ავტომატურად აკონვერტებს პროექტის სურათებს (Next.js-ის `<Image>` სწორედ ამას იყენებს კულისებში). **Cloudinary/imgix** — CDN სერვისები, სადაც URL-ის პარამეტრებით ნებისმიერ ზომას/ფორმატს ითხოვ (on-the-fly), წინასწარ მომზადება არ გჭირდება.

## 3.2 ფონტების ოპტიმიზაცია

### font-display:

> **`@font-face` — რა არის?** ფონტის რეგისტრაცია CSS-ში. ბრაუზერს ეუბნები: "ამ სახელის ფონტი ამ ფაილიდან ჩამოტვირთე". იწერება CSS ფაილის დასაწყისში, სტილებამდე. მერე `font-family`-ში იმ სახელით იყენებ. Google Fonts-ის ნაცვლად შეგიძლია ფონტის ფაილი (.woff2) პროექტში გქონდეს და `@font-face`-ით ჩატვირთო — ოპტიმიზაციის კუთხით უკეთესია, რადგან Google-ის სერვერთან დამატებითი კავშირის დამყარება აღარ სჭირდება ბრაუზერს.
>
> **ფონტის ფაილი** — ფაილი, რომელშიც ასოების ვიზუალური დიზაინია შენახული (ფორმა, სისქე, დახრილობა). მაგალითად `Roboto.woff2`.
>
> **`format('woff2')`** — ბრაუზერს ეუბნები რა ფორმატისაა ფაილი, რომ ტყუილად არ ჩამოტვირთოს ფორმატი, რომელიც არ იცის. რამდენიმე ფორმატის მითითება შეიძლება fallback-ით (ჯერ woff2, შემდეგ woff).

```css
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap; /* ტექსტი მაშინვე ჩანს system font-ით, შემდეგ იცვლება */
}

/* შემდეგ იყენებ ჩვეულებრივად */
body {
  font-family: 'CustomFont', Arial, sans-serif;
  /* Arial, sans-serif არის fallback/"სისტემური ფონტი" — 
     swap დროს ბრაუზერი ამას აჩვენებს სანამ CustomFont ჩაიტვირთება */
}
```

- **block** — ტექსტი **საერთოდ არ ჩანს** სანამ ფონტი არ ჩაიტვირთება. ცუდია, რადგან მომხმარებელი ცარიელ ეკრანს ხედავს.
- **swap** — ტექსტი **მაშინვე ჩანს** სისტემური ფონტით, ფონტის ჩატვირთვის შემდეგ იცვლება custom-ზე — **რეკომენდებული**
- **fallback** — swap-ის მსგავსია, მაგრამ თუ ფონტი რამდენიმე წამში არ ჩაიტვირთა, სისტემურ ფონტზე რჩება და აღარ იცვლება
- **optional** — თუ ფონტი ძალიან სწრაფად ჩაიტვირთა (მაგ. ქეშში იყო), იყენებს, თუ არა — სისტემურს ტოვებს. ყველაზე მკაცრი performance-ის კუთხით

### WOFF2 ფორმატი:
- ყოველთვის გამოიყენეთ WOFF2 — 30% უფრო მცირეა WOFF-ზე
- 97%+ ბრაუზერების მხარდაჭერა

> **WOFF/WOFF2 არის ფონტის ფორმატები** (არა სურათის). WOFF იყენებს gzip კომპრესიას, WOFF2 — Brotli კომპრესიას, რომელიც უფრო ეფექტურია. შედეგად იგივე ფონტი WOFF2-ში ~30%-ით პატარაა, ხარისხის განსხვავების გარეშე.

### Google Fonts ოპტიმიზაცია:
```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&display=swap" rel="stylesheet">
```
