## ბაგი #1 — Missing useEffect Cleanup

**ფაილი:** `src/components/StreakBadge.jsx`

```jsx
// ❌ before
useEffect(() => {
  const interval = setInterval(() => {
    console.log('⏱ StreakBadge tick')
    setTimeSinceLastAdd(prev => prev + 1)
  }, 1000)
}, [])

// ✅ after
useEffect(() => {
  const interval = setInterval(() => {
    setTimeSinceLastAdd(prev => prev + 1)
  }, 1000)
  return () => clearInterval(interval)
}, [])
```

**რატომ +2:** StrictMode-ში development-ში effect ორჯერ სრულდება (mount → unmount → mount). cleanup-ის გარეშე პირველი interval არ იშლება → ორი interval წამში ორ ტიკს აკეთებს.

**რატომ leak:** როცა `habits.length === 0`, `StreakBadge` unmount-დება (`HabitTracker.jsx`-ში პირობითი რენდერი), მაგრამ interval აგრძელებს მუშაობას — Console-ში `⏱ StreakBadge tick` ისმის და `setState` unmount-ულ კომპონენტზე გამოიძახება.

**ინსტრუმენტი:** Console (ტიკების დათვლა), Performance/Memory ჩანაწერი.

## ბაგი #2 — Direct State Mutation

**ფაილი:** `src/components/HabitTracker.jsx` → `toggleHabit`

```jsx
// ❌ before
const toggleHabit = (id) => {
  const habit = habits.find(h => h.id === id)
  habit.doneToday = !habit.doneToday
  habit.streak = habit.doneToday ? habit.streak + 1 : habit.streak - 1
  setHabits(habits)
}

// ✅ after
const toggleHabit = (id) => {
  setHabits(prevHabits => prevHabits.map(habit =>
    habit.id === id
      ? {
          ...habit,
          doneToday: !habit.doneToday,
          streak: habit.doneToday ? habit.streak - 1 : habit.streak + 1
        }
      : habit
  ))
}
```

**რატომ:** `setHabits(habits)` — მასივის reference იგივეა, React `Object.is`-ით ადარებს და re-render-ს არ იწყებს. ობიექტიც პირდაპირ იცვლება.

**დამატებითი დაკვირვება:** ცვლილება „უცებ ჩნდება" შემდეგ re-render-ზე (მაგ. ახალი ჩვევის დამატებისას) — კლასიკური ნიშანი მუტაციისა.

**ინსტრუმენტი:** React DevTools → Components → `habits` state.

## ბაგი #3 — Missing useEffect Dependency

**ფაილი:** `src/components/HabitTracker.jsx` → ფილტრაციის `useEffect`

```jsx
// ❌ before
}, [habits])

// ✅ after
}, [habits, filter])
```

**რატომ:** effect მხოლოდ `habits`-ის ცვლილებაზე სრულდება, `filter`-ის ცვლილება მას არ ტრიგერავს → `visibleHabits` ძველი რჩება.

**ალტერნატიული (უკეთესი) გამოსწორება:** `visibleHabits` state-ს საერთოდ არ სჭირდება — derived value-ად გამოთვლა:

```jsx
const visibleHabits = filter === 'all'
  ? habits
  : habits.filter(h => filter === 'done' ? h.doneToday : !h.doneToday)
```

თუ სტუდენტმა ეს ვარიანტი აირჩია — სრული ქულა (ეს არის React-ის რეკომენდებული მიდგომა).

**ინსტრუმენტი:** ESLint `react-hooks/exhaustive-deps` warning, breakpoint effect-ის შიგნით.

## ბაგი #4 — Stale Closure

**ფაილი:** `src/components/HabitTracker.jsx` → `deleteHabitDelayed`

```jsx
// ❌ before
setTimeout(() => {
  setHabits(habits.filter(habit => habit.id !== id))
}, 5000)

// ✅ after
setTimeout(() => {
  setHabits(prev => prev.filter(habit => habit.id !== id))
}, 5000)
```

**რატომ:** `habits` closure-ში „გაიყინა" ღილაკზე დაჭერის მომენტში. 5 წამის შემდეგ state ამ ძველი მასივით ჩანაცვლდება → ამ დროში დამატებული ჩვევები ქრება.

**ინსტრუმენტი:** breakpoint callback-ში → Scope → Closure → `habits`.

## ბაგი #6 — Async Race Condition

**ფაილი:** `src/components/HabitTracker.jsx` → `addHabit`

```jsx
// ❌ before
setTimeout(() => {
  setHabits([...habits, newHabit])
}, 150)

// ✅ after
setTimeout(() => {
  setHabits(prev => [...prev, newHabit])
}, 150)
```

**რატომ:** 150მწ დაყოვნებით ორი-სამი callback ერთსა და იმავე ძველ `habits`-ს იყენებს → ბოლო წერს ყველას თავზე („last write wins"), შუალედური ჩანაწერები იკარგება.

**დამატებით (არასავალდებულო):** `setAddCounter(addCounter + 1)` → `setAddCounter(prev => prev + 1)` — იგივე ტიპის პრობლემა, ბონუს ქულისთვის.

**ინსტრუმენტი:** breakpoint `setTimeout` callback-ში, Scope → `habits.length`.

**ტიპური შეცდომები სტუდენტების პასუხებში:**

- ბაგი #4-ისა და #6-ის ერთ ბაგად აღქმა — ორივე stale state-ია, მაგრამ სხვადასხვა ფუნქციაშია და ცალკე უნდა გამოსწორდეს.
- ბაგი #1-ზე მხოლოდ „+2" სიმპტომის აღწერა memory leak-ის ნაწილის გარეშე.
