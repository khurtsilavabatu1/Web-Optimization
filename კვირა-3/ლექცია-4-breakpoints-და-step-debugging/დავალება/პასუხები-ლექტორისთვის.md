## ბაგი #1 — Off-by-One ციკლში

**ფაილი:** `src/utils/billing.js` → `calculateSubtotal`

```js
// ❌ before
for (let i = 1; i < items.length; i++) {
  subtotal += items[i].price * items[i].quantity;
}

// ✅ after
for (let i = 0; i < items.length; i++) {
  subtotal += items[i].price * items[i].quantity;
}
```

**ალტერნატიული გამოსწორება (სრული ქულა):**

```js
const subtotal = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
```

**Scope-ში სტუდენტმა უნდა დაინახოს:** ერთი ელემენტისას ციკლი **ვერც ერთხელ** არ სრულდება (`i = 1`, `items.length = 1`), ორისას მხოლოდ ერთხელ.

**შემოწმება:** ხაჭაპური 12.50 + მწვადი 24.00 = 36.50 ₾.

## ბაგი #2 — String + Number (ტიპების ბაგი)

**ფაილები:** `src/utils/billing.js` → `nextQuantity`, `src/components/MenuCard.jsx` → `useState('1')`

```js
// ❌ before (billing.js)
export function nextQuantity(value) {
  const result = value + 1;   // '1' + 1 = '11'
  return result;
}

// ✅ after
export function nextQuantity(value) {
  const result = Number(value) + 1;
  return result;
}
```

**ალტერნატიული (ასევე სწორი) გამოსწორება:** `MenuCard.jsx`-ში `useState(1)` — რიცხვით, სტრიქონის ნაცვლად. თუ სტუდენტმა ორივე გააკეთა — სრული ქულა + ბონუსი.

**რატომ მუშაობს „−":** `-` ოპერატორს მხოლოდ არითმეტიკული მნიშვნელობა აქვს, ამიტომ `'1' - 1` → `0` (ტიპი ავტომატურად კონვერტირდება). `+` ოპერატორი კი სტრიქონთან **კონკატენაციას** ნიშნავს → `'1' + 1` = `'11'`.

**რას უნდა აჩვენოს სტუდენტმა:** F11-ით `MenuCard.handlePlus`-იდან `billing.js`-ის `nextQuantity`-ში შესვლა და Scope-ში `value: "1"` (ბრჭყალებით — ეს არის მთავარი მინიშნება), ან Console-ში `typeof value` → `"string"`.

## ბაგი #3 — არასწორი property გამოძახებაში

**ფაილი:** `src/components/BillItem.jsx` → `handleRemove`

```jsx
// ❌ before
const handleRemove = () => {
  onRemove(item.dishId);   // ობიექტს არ აქვს dishId
};

// ✅ after
const handleRemove = () => {
  onRemove(item.id);
};
```

**რატომ არ ჩანს შეცდომა:** არარსებული property JavaScript-ში `undefined`-ს აბრუნებს (და არა შეცდომას). შემდეგ `App.handleRemoveDish(undefined)` → `filter(item => item.id !== undefined)` → ყველა ელემენტი პირობას აკმაყოფილებს → მასივი უცვლელი რჩება. ეს **Logic Error**-ია: კოდი „მუშაობს", მაგრამ არასწორად.

**Logpoint (რეკომენდებული ადგილი):** `App.jsx` → `handleRemoveDish`-ის პირველ ხაზზე:
```
dishId:', dishId, 'order ids:', order.map(i => i.id)
```

**Call Stack:** `handleRemove (BillItem.jsx) → handleRemoveDish (App.jsx)` — აქედან ჩანს, სად უნდა ვეძებოთ მიზეზი (გამოძახების ადგილი და არა თავად filter).

## ბაგი #4 — ვალიდაციის ნაკლებობა (Runtime Error)

**ფაილი:** `src/components/CloseBill.jsx` → `handleCloseBill`

```jsx
// ❌ before
setIsProcessing(true);
const firstDishName = order[0].name;

// ✅ after
if (order.length === 0) {
  alert('ანგარიში ცარიელია! ჯერ კერძი დაამატეთ.');
  return;
}

setIsProcessing(true);
const firstDishName = order[0].name;
```

**შეცდომის ტექსტი:** `Uncaught TypeError: Cannot read properties of undefined (reading 'name')`

**რატომ რჩება ღილაკი „დამუშავება..." რეჟიმში:** `setIsProcessing(true)` შეცდომამდე შესრულდა, ხოლო `setIsProcessing(false)` შეცდომის შემდეგ **აღარ სრულდება** — ფუნქცია შეწყდა. ღილაკი `disabled` რჩება გვერდის განახლებამდე. ეს კარგი მაგალითია იმისა, რომ exception-ი state-ს **არასრულ მდგომარეობაში** ტოვებს.

**დამატებითი სწორი ვარიანტი (ბონუსი):** `try / catch / finally`, სადაც `finally`-ში `setIsProcessing(false)`.

## ბაგი #5 — parseInt და ათწილადები

**ფაილი:** `src/utils/billing.js` → `calculateServiceFee`

```js
// ❌ before
const fee = subtotal * (servicePercent / 100);
const roundedFee = parseInt(fee);      // 6.75 → 6

// ✅ after
const fee = subtotal * (servicePercent / 100);
const roundedFee = Math.round(fee * 100) / 100;   // 6.75 → 6.75
```

**რატომ:** `parseInt` სტრიქონიდან **მთელ** რიცხვს კითხულობს და ათწილადს ჭრის (`parseInt(6.75)` → `6`). ფინანსურ გამოთვლებში ეს ყოველთვის ბაგია.

**Conditional breakpoint-ის საჭიროება:** `calculateServiceFee` **ყოველ რენდერზე** იძახება (`Bill.jsx`-ის სხეულში), ამიტომ ჩვეულებრივი breakpoint ყოველ დაწკაპუნებაზე გააჩერებს კოდს. პირობა `servicePercent === 15 && subtotal > 40` ზუსტად საჭირო მომენტს გამოყოფს.

**Watch-ის მოსალოდნელი მნიშვნელობები (45.00 ₾, 15%):** `subtotal * (servicePercent / 100)` = `6.75`, `fee` = `6.75`, `roundedFee` = `6`.

**შემოწმება გამოსწორების შემდეგ:** მომსახურება 6.75 ₾, ჯამი 51.75 ₾, 3 ადამიანზე 17.25 ₾.

## დამატებითი სავარჯიშოების პასუხები

**7.1 DOM Breakpoint** — Call Stack სტუდენტთან შეიძლება ოდნავ განსხვავდებოდეს React-ის ვერსიის მიხედვით, მაგრამ უნდა შეიცავდეს React-ის commit ფაზის ფუნქციებს (`commitMutationEffects` და მსგავსი) — მთავარია სტუდენტმა ახსნას, რომ DOM-ს **React ცვლის**, არა თავად handler.

**7.2 Event Listener Breakpoint** — click-ზე შეჩერება React-ის synthetic event სისტემაში (`dispatchDiscreteEvent`) ხდება — კარგი შემთხვევაა იმის ჩვენების, რომ React ყველა click-ს root-ზე იჭერს (event delegation).

**7.3 Scope-ის სამი დონე** — Local: `subtotal`, `servicePercent`, `fee`; Closure/Module: `SERVICE_RATES`, `TAX`-ის მსგავსი მოდულის დონის ცვლადები; Global: `window`, `document`.
