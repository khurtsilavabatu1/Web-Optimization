# ლექცია 1 — კარგი vs ცუდი მაგალითის ანალიზი

## როგორ გავუშვათ ლოკალურად

ორივე პროექტი pure HTML/CSS/JS-ია — npm install არ სჭირდება.

### გაშვება (ტერმინალიდან):
```bash
# ცუდი მაგალითი
cd კვირა-1/ლექცია-1/ცუდი-მაგალითი
python3 -m http.server 8080

# მეორე ტერმინალში — კარგი მაგალითი
cd კვირა-1/ლექცია-1/კარგი-მაგალითი
python3 -m http.server 8081
```

შემდეგ გახსენით:
- ცუდი: http://localhost:8080
- კარგი: http://localhost:8081

### ანალიზისთვის:
1. **Chrome DevTools** → Network tab (F12) — გვერდის ზომა, რესურსების რაოდენობა
2. **Performance tab** → Record → შეაჩერეთ → ნახეთ Long Tasks
3. **Lighthouse** → Analyze page load → შეადარეთ ქულები
4. **Console** → ორივე პროექტი ავტომატურად ბეჭდავს მეტრიკებს Console-ში

## მეტრიკების შედარება

| მეტრიკა | ❌ ცუდი მაგალითი | ✅ კარგი მაგალითი | რატომ? |
|---------|----------------|-----------------|--------|
| **Page Size** | ~20MB+ (10 × 2MB სურათი + libs) | ~500KB (10 × 50KB სურათი) | სურათები w=3000 vs w=600, libs არ არის |
| **JS Bundle** | ~400KB (lodash 70KB + moment 300KB) | ~5KB (native JS only) | Native API-ები ბიბლიოთეკების ნაცვლად |
| **Render-blocking** | 5 ფაილი (2 CSS + 2 JS + @import) | 0 (critical CSS inline, JS defer) | defer + inline critical CSS |
| **LCP** | 4-8 წამი | 1-2 წამი | სურათების ოპტიმიზაცია, no blocking |
| **CLS** | 0.3+ | < 0.05 | img dimensions, reserved banner space |
| **Long Tasks** | 4+ (heavyComputation ×3, render 1000 rows) | 0 | no heavy sync computation |
| **INP** | 500ms+ (search = heavyComputation) | < 100ms | debounce + no computation |
| **DOM Nodes** | 5000+ (1000 rows × 5 cells) | 250+ (50 rows × 5 cells) | Pagination |

## პრობლემა → გადაწყვეტა — დეტალური ცხრილი

### 1. Page Size (გვერდის ზომა)

| პრობლემა (ცუდი) | გადაწყვეტა (კარგი) |
|-----------------|-------------------|
| სურათები w=3000 (~2MB თითო) | სურათები w=600, q=75 (~50KB თითო) |
| lodash.js მთლიანი (70KB) | Native Array.sort() (0KB) |
| moment.js მთლიანი (300KB) | Intl.DateTimeFormat (0KB) |
| animate.css (80KB) | CSS animation inline (0KB) |
| font-awesome (300KB) | არ გამოიყენება / SVG icons |

### 2. LCP (Largest Contentful Paint)

| პრობლემა (ცუდი) | გადაწყვეტა (კარგი) |
|-----------------|-------------------|
| Render-blocking JS ბლოკავს parsing-ს | `<script defer>` |
| Render-blocking CSS (@import) | Critical CSS inline |
| დიდი სურათები ნელა იტვირთება | ოპტიმიზირებული ზომა + preconnect |
| preconnect არ არის | `<link rel="preconnect">` |

### 3. CLS (Cumulative Layout Shift)

| პრობლემა (ცუდი) | გადაწყვეტა (კარგი) |
|-----------------|-------------------|
| `<img>` width/height გარეშე | `width="280" height="200"` |
| ბანერი ჩაისმება ადგილის გარეშე | `min-height: 100px` container |
| ფონტი `display:block` — ელოდება | `display:swap` — მაშინვე ჩანს |
| CSS @import — ნელი ჩატვირთვა | inline critical CSS |

### 4. INP / TBT (Main Thread Blocking)

| პრობლემა (ცუდი) | გადაწყვეტა (კარგი) |
|-----------------|-------------------|
| heavyComputation() — 10M iterations | წაშლილია (არ სჭირდება) |
| ძებნა debounce-ის გარეშე | debounce 300ms |
| 1000 row ერთდროულად | Pagination — 50 row |
| scroll handler — heavy computation | requestAnimationFrame |
| moment() ყოველ row-ზე | Intl.DateTimeFormat — cached |

## რას ვაკვირდებით DevTools-ში

### Network Tab:
1. **ცუდი:** ქვედა ზოლში `transferred: 20MB+`, `requests: 25+`
2. **კარგი:** ქვედა ზოლში `transferred: ~500KB`, `requests: 15`

### Performance Tab:
1. **ცუდი:** Main Thread-ზე ჩანს წითელი კუთხეები (Long Tasks 50ms+)
   - heavyComputation: ~200-500ms
   - renderAllProducts: ~100-200ms
   - search handler: ~300-500ms (ყოველ keystroke-ზე!)
2. **კარგი:** Long Tasks არ ჩანს, Main Thread „სუფთაა"

### Console:
ორივე პროექტი ავტომატურად ბეჭდავს:
- TTFB, DOM Content Loaded, Load Event
- Total Transfer Size
- LCP timing
- CLS score (layout shift-ების თითოეული)

### Lighthouse:
1. **ცუდი:** Performance Score ~30-50
2. **კარგი:** Performance Score ~85-95
