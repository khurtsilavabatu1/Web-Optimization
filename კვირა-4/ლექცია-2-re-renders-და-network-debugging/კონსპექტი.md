# ლექცია 2 — ზედმეტი Re-renders და Network Debugging

## 2.1 Re-render-ების პრევენცია

```jsx
// ❌ პრობლემა: Parent-ის ყოველ render-ზე Child-იც რენდერდება
function Parent() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>+</button>
      <ExpensiveChild /> {/* ყოველ click-ზე რენდერდება! */}
    </div>
  );
}

// ✅ React.memo
const ExpensiveChild = React.memo(function ExpensiveChild() {
  return <div>...</div>;
});

// ✅ useMemo — მძიმე გამოთვლებისთვის
function ProductList({ items, filter }) {
  const filteredItems = useMemo(
    () => items.filter(item => item.category === filter),
    [items, filter] // მხოლოდ items ან filter-ის ცვლილებაზე გადაითვლება
  );
  return filteredItems.map(item => <ProductCard key={item.id} item={item} />);
}

// ✅ useCallback — callback-ებისთვის
function Parent() {
  const [items, setItems] = useState([]);
  
  const handleDelete = useCallback((id) => {
    setItems(prev => prev.filter(item => item.id !== id));
  }, []); // ფუნქცია არ იცვლება — child არ რენდერდება ხელახლა
  
  return <ItemList items={items} onDelete={handleDelete} />;
}
```

## 2.2 Network Debugging

### API Calls-ის ინსპექტირება:
```
Network tab → Filter: XHR/Fetch
Request-ზე click:
  Headers → URL, Method, Status Code, Authorization
  Payload → Request body
  Response → Response data
  Timing → TTFB, Download
```

### CORS Debugging:
```
// ტიპიური შეცდომა Console-ში:
// Access to fetch at 'https://api.example.com' from origin 
// 'http://localhost:5173' has been blocked by CORS policy

// გამოსწორება 1: Backend-ზე (Express.js)
app.use(cors({ origin: 'http://localhost:5173' }));

// გამოსწორება 2: Dev proxy (Vite)
// vite.config.js
export default {
  server: {
    proxy: {
      '/api': {
        target: 'https://api.example.com',
        changeOrigin: true,
      },
    },
  },
};
```

### Fetch/XHR Breakpoints:
```
Sources → XHR/fetch Breakpoints → +
URL contains: "api/users"
→ ყოველ ამ API call-ზე გაჩერდება
```
