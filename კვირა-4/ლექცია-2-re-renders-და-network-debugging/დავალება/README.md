## აღწერა

მოცემულია **Support Inbox** — React აპლიკაცია სუპორტის ტიკეტებისთვის: ძიება, პრიორიტეტის
ფილტრი, აგენტის მიბმა, SLA ანგარიში და API პანელი. აპი გარეგნულად მუშაობს, მაგრამ შიგნით
**6 პრობლემაა — 3 ქსელის და 3 რენდერის/memoization-ის** — იგივე ტიპის, რაც ლექციის გაიდში
(`../GUIDE.md`) `demo-rerender-network`-ზე განვიხილეთ, ოღონდ **სხვა დომენში და სხვა კოდში**.

განსხვავება ლექციის პროექტისგან:

- აქ **Before/After სვეტები არ არის** — ერთი აპია და თქვენ თვითონ უნდა აქციოთ ის „After"-ად

- გვერდის ბოლოს პანელი მხოლოდ **სიმპტომს** და გამეორების ნაბიჯებს აღწერს
- თითოეული პრობლემისთვის **სავალდებულოა კონკრეტული ინსტრუმენტის გამოყენება**

**შენი ამოცანა:** იპოვე 6-ვე პრობლემა მითითებული ინსტრუმენტით, გამოასწორე და

## წინაპირობა

```bash
cd ~/Desktop/Web-optimization/კვირა-4/ლექცია-2-re-renders-და-network-debugging/დავალება/homework-rerender-network
npm install
npm run dev
```

გახსენით `http://localhost:5173` → DevTools (F12) → **Network** და **Profiler** ტაბები.

გჭირდებათ:

- Chrome extension **React Developer Tools** (თუ არ გაქვთ — `../../ლექცია-1-vscode-debugger-და-react-devtools/GUIDE.md`, ეტაპი 1)
- Network tab-ში ფილტრი **Fetch/XHR** (რომ CSS/JS/სურათები არ ჩანდეს)

> გადაიკითხეთ `../GUIDE.md`: ეტაპი 1-2 (render counter-ები, Profiler), ეტაპი 4
> (`React.memo`, `useMemo`, `useCallback`), ეტაპი 5-6 (Network tab, სტატუს კოდები),
> ეტაპი 7 (CORS და proxy).

**პროექტში StrictMode გამორთულია** — ამიტომ `renders: N` badge-ები ზუსტად ინტერაქციების
რაოდენობას აჩვენებენ და ცხრილებში ჩაწერილი რიცხვები შედარებადია.

**ლოკალური endpoint-ები** (`public/`): `/tickets.json`, `/agents.json`, `/sla-targets.json` — 200;
`/tickets-archive.json` — **404** (ფაილი განზრახ არ არსებობს). ინტერნეტი მხოლოდ
„დისტანციური request" და „CORS ტესტი" ღილაკებს სჭირდება.
