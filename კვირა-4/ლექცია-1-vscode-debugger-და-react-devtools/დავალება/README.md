## აღწერა

მოცემულია **Playlist Studio** — React აპლიკაცია მუსიკის ბიბლიოთეკისთვის: ტრეკების ძიება,
პლეილისტში დამატება და ბიბლიოთეკის სტატისტიკა. აპი გარეგნულად მუშაობს, მაგრამ შიგნით
**5 ბაგი + 1 წარმადობის პრობლემაა** — იგივე ტიპის, რაც ლექციის გაიდში (`../GUIDE.md`)
`demo-react-devtools`-ზე განვიხილეთ, ოღონდ **სხვა დომენში და სხვა კოდში**.

განსხვავება ლექციის პროექტისგან:

- კოდში `// BUG #N` კომენტარები **არ არის**
- გვერდის ბოლოს პანელი მხოლოდ **სიმპტომს** და გამეორების ნაბიჯებს აღწერს
- თითოეული პრობლემისთვის **სავალდებულოა კონკრეტული ინსტრუმენტის გამოყენება** (ქვემოთ მითითებულია)

**შენი ამოცანა:** იპოვე 5 ბაგი მითითებული ინსტრუმენტით, გამოასწორე, დაადასტურე შედეგი
და დაასვი დიაგნოზი წარმადობის პრობლემას Profiler-ით.

> ⚠️ **მთავარი წესი:** ბაგი „თვალით" კოდის კითხვით რომ იპოვო, ეს დავალება არ ითვლება შესრულებულად.

## წინაპირობა

```bash
cd ~/Desktop/Web-optimization/კვირა-4/ლექცია-1-vscode-debugger-და-react-devtools/დავალება/homework-react-devtools
npm install
npm run dev
```

გახსენით `http://localhost:5173` → DevTools (F12) → **Components** და **Profiler** ტაბები.

გჭირდებათ:

- Chrome extension **React Developer Tools** (თუ არ გაქვთ — `../GUIDE.md`, ეტაპი 1)
- **VS Code**, გახსნილი ფოლდერით `homework-react-devtools` (File → Open Folder).
  `.vscode/launch.json` პროექტში უკვე არის და `${workspaceFolder}`-ს იყენებს —
  თუ მთელი რეპოზიტორია გაქვთ გახსნილი, `webRoot` შესაბამისად შეასწორეთ.

> გადაიკითხეთ `../GUIDE.md`: ეტაპი 2 (Components), 3 (State editing), 4 (Highlight updates),
> 5-6 (Profiler, „Why did this render?"), 8 (VS Code Debugger).

**პროექტში StrictMode გამორთულია** — ამიტომ `renders: N` badge-ები ზუსტად ინტერაქციების
რაოდენობას აჩვენებენ და ცხრილებში ჩაწერილი რიცხვები შედარებადია.
