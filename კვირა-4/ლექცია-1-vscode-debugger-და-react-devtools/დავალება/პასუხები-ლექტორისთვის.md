## ბაგი #1 — არასწორი property-ს შედარება

**ფაილი:** `src/App.jsx` → `handleAddTrack`

```js
// ❌ before
const existing = prevPlaylist.find(item => item.id === track.trackId)

// ✅ after
const existing = prevPlaylist.find(item => item.id === track.id)
```

`track.trackId` არ არსებობს → `undefined` → `existing` ყოველთვის `undefined` →
`if (existing)` არასოდეს სრულდება → ყოველი დაჭერა ახალ მწკრივს ამატებს.

**რას ხედავს სტუდენტი Components tab-ში:** `PlaylistPanel` → props → `playlist` =
ორი ობიექტი **ერთი და იმავე `id`-თ** და `count: 1`.

**დამატებითი მინიშნება:** `PlaylistPanel` `key={item.id}`-ს იყენებს, ამიტომ Console-ში ჩნდება
React-ის warning: *"Encountered two children with the same key"*. ეს არის ლეგიტიმური მინიშნება —
ბაგი `key`-ში არ არის, `key` მხოლოდ სიმპტომს ამხელს.

**VS Code VARIABLES:** `existing: undefined`, `prevPlaylist.length: 1`, `track.id: 1`.

**რატომ არ არის წითელი შეცდომა:** არარსებული property-ს წაკითხვა JavaScript-ში
`undefined`-ს აბრუნებს და არა შეცდომას (`TypeError` მხოლოდ `undefined`-ის property-ს
წაკითხვისას იქნებოდა).

**შემოწმება:** ერთი მწკრივი `x2`; key warning ქრება.

## ბაგი #2 — Case-sensitive ძიება

**ფაილი:** `src/App.jsx` → `visibleTracks`

```js
// ❌ before
return track.title.includes(searchTerm)

// ✅ after
return track.title.toLowerCase().includes(searchTerm.toLowerCase())
```

**რას ხედავს სტუდენტი:** `App` → hooks → `State: searchTerm`-ის ხელით შეცვლით —
`Midnight` → 1 ტრეკი, `midnight` → 0. ეს ადასტურებს, რომ პრობლემა შედარებაშია და
არა `onChange`-ში ან input-ში.

**მოსალოდნელი ცხრილი (გასწორებამდე):**

| `searchTerm` | ნაპოვნია |
|---|---|
| `Midnight` | 1 |
| `midnight` | 0 |
| `MIDNIGHT` | 0 |
| `rain` | 0 |
| `Rain` | 1 (Neon Rain) |

**შემოწმება (გასწორების შემდეგ):** `midnight` → 1, `NEON` → 1, `rain` → 1,
`ელექტრონული` + `rain` → 1.

**კითხვის პასუხი:** DevTools-იდან state-ის შეცვლა გვერდის ავლით უვლის input-ის, `onChange`-ის
და React-ის მთელ ჯაჭვს — ერთი ცვლადის იზოლირებული ტესტია, „ერთი ცვლადი ერთ დროს" პრინციპი.

## ბაგი #3 — `key={index}` და ლოკალური state

**ფაილი:** `src/components/TrackList.jsx`

```jsx
// ❌ before
{tracks.map((track, index) => (
  <TrackCard key={index} track={track} ... />
))}

// ✅ after
{tracks.map(track => (
  <TrackCard key={track.id} track={track} ... />
))}
```

`index`-ის `key`-ად გამოყენებისას სიის შემცირებაზე React **პოზიციას** ინარჩუნებს და არა
იდენტობას: index 2-ის კომპონენტის ინსტანცია (და მისი `showDetails: true`) რჩება,
props კი სხვა ტრეკის ხდება.

**სცენარი:** „დეტალები" Paper Boats-ზე (index 2) → 🚫 Midnight Drive-ზე (index 0) →
Paper Boats index 1-ზე გადმოინაცვლებს, index 2 = Solar Wind, რომელსაც
დეტალები აქვს გახსნილი.

**Console-ის მინიშნება:** unmount ილოგება **ბოლო** ბარათზე (`First Frost`) და არა
წაშლილზე (`Midnight Drive`) — ეს ცხადად ამხელს, რომ React პოზიციებით მუშაობს.
გასწორების შემდეგ ილოგება სწორედ `👋 TrackCard unmounted: Midnight Drive`.

**მეორე სიმპტომი:** გახსენით დეტალები და აკრიფეთ ძიებაში — ფილტრაციის შემდეგ დეტალები
სხვა ტრეკზე აღმოჩნდება (იმავე მიზეზით).

**`key={index}` უსაფრთხოა მხოლოდ მაშინ,** როცა სია სტატიკურია: არ იშლება, არ ემატება,
არ ლაგდება და ელემენტებს ლოკალური state/uncontrolled input არ აქვთ.

## ბაგი #4 — `formatDuration`: `Math.round` + padding

**ფაილი:** `src/utils/playlist.js`

```js
// ❌ before
export function formatDuration(totalSeconds) {
  const minutes = Math.round(totalSeconds / 60)
  const seconds = totalSeconds % 60
  return `${minutes}:${seconds}`
}

// ✅ after
export function formatDuration(totalSeconds) {
  const minutes = Math.floor(totalSeconds / 60)
  const seconds = totalSeconds % 60
  return `${minutes}:${String(seconds).padStart(2, '0')}`
}
```

**ორი დეფექტი:** (1) `Math.round` წუთს ზემოთ ამრგვალებს, როცა წამები 30-ს აღემატება;
(2) წამები არ არის ორნიშნა (`2:9`).

**მოსალოდნელი ცხრილი:**

| ტრეკი | წამები | buggy | სწორი |
|---|---|---|---|
| Midnight Drive | 225 | 4:45 ❌ | 3:45 |
| Neon Rain | 245 | 4:5 ❌ | 4:05 |
| Paper Boats | 198 | 3:18 ✅ | 3:18 |
| Solar Wind | 342 | 6:42 ❌ | 5:42 |
| Blue Marani | 310 | 5:10 ✅ | 5:10 |
| Echo Chamber | 288 | 5:48 ❌ | 4:48 |
| Night Bus | 154 | 3:34 ❌ | 2:34 |
| Amber Light | 203 | 3:23 ✅ | 3:23 |
| Slow Motion | 260 | 4:20 ✅ | 4:20 |
| First Frost | 129 | 2:9 ❌ | 2:09 |

**რატომ არის ზოგი შემთხვევით სწორი:** როცა `totalSeconds % 60 < 30`, `Math.round`
და `Math.floor` ერთსა და იმავეს იძლევა (და წამები ორნიშნაა). ეს კარგი მომენტია
იმის საჩვენებლად, რომ „ნაწილობრივ სწორი" შედეგი ბაგს არ გამორიცხავს.

**საშუალო ხანგრძლივობა:** 2354 / 10 = 235 წამი → buggy `4:55`, სწორი **3:55**.

## ბაგი #5 — ჯამში `count` არ მონაწილეობს

**ფაილი:** `src/utils/playlist.js`

```js
// ❌ before
export function totalPlaylistSeconds(playlist) {
  return playlist.reduce((sum, item) => sum + item.duration, 0)
}

// ✅ after
export function totalPlaylistSeconds(playlist) {
  return playlist.reduce((sum, item) => sum + item.duration * item.count, 0)
}
```

**რატომ ჩანს მხოლოდ #1-ის შემდეგ:** სანამ #1 არ არის გასწორებული, გამეორებები ცალკე
მწკრივებად ემატება და ჯამი „შემთხვევით" სწორია. `x2`, `x3` მწკრივები მხოლოდ #1-ის
შემდეგ ჩნდება.

**კონტრასტი:** `totalPlaylistTracks` სწორად იყენებს `item.count`-ს — ამიტომ
„სულ: 4 ტრეკი" სწორია, დრო კი არა. სწორედ ეს კონტრასტი ავიწროებს ძებნის არეს ერთ ფუნქციამდე.

**შემოწმება:** `Midnight Drive x3 + Neon Rain x1` → 225×3 + 245 = 920 წამი = **15:20**
(buggy: 470 → `8:50`; `formatDuration`-ის გასწორებამდე კიდევ სხვა რიცხვი).

## პრობლემა #6 — ნელი აკრეფა (მხოლოდ დიაგნოზი)

   არასოდეს იცვლება.
2. **ზედმეტი რენდერი** — `React.memo` არსად არ არის, ამიტომ `App`-ის ყოველი state ცვლილება

3. **არასტაბილური props** — `App.jsx`-ში `settings={{ showFingerprint: true, locale: 'ka-GE' }}`

**Profiler-ის მოსალოდნელი სურათი:** Ranked view-ში #1 — `StatsFooter` (~20-40 ms),
დანარჩენები 1 ms-ის ფარგლებში; commit-ის ჯამი ≈ StatsFooter-ის დრო.

**„Why did this render?" მოსალოდნელი პასუხები:**

**მოსალოდნელი დიაგნოზი სტუდენტისგან:** `computeLibraryStats` უნდა დაიმახსოვროს
