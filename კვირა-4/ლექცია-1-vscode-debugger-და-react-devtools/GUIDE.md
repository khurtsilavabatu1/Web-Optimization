# React DevTools — ეტაპობრივი გაიდი

ამ პრაქტიკაში თქვენ იმუშავებთ **Product Dashboard** React აპლიკაციაზე და ისწავლით React DevTools-ის გამოყენებას — კომპონენტების ხის ინსპექტირებას, state-ის ცოცხალ რედაქტირებას, რენდერინგის ვიზუალიზაციას და Profiler-ით წარმადობის ანალიზს. აპლიკაცია **განზრახ არ იყენებს** `React.memo`, `useMemo` ან `useCallback` ოპტიმიზაციებს, რათა DevTools-ით ნათლად დაინახოთ ზედმეტი რენდერების პრობლემა.

პროექტი მდებარეობს `demo-react-devtools/` ფოლდერში.

**პროექტი არის სრული Vite + React აპლიკაცია** შემდეგი სტრუქტურით:
- **`src/App.jsx`** — მთავარი კომპონენტი, state მენეჯმენტი
- **`src/components/SearchBar.jsx`** — საძიებო ველი
- **`src/components/ProductList.jsx`** — პროდუქტების სია
- **`src/components/ProductCard.jsx`** — ცალკეული პროდუქტის ბარათი
- **`src/components/CartSummary.jsx`** — კალათის შეჯამება

## ეტაპი 1: React DevTools-ის ინსტალაცია

### 1.1 Extension-ის დაყენება

1. Chrome Web Store-ში მოძებნეთ **"React Developer Tools"**
2. დააჭირეთ **"Add to Chrome"** → დაინსტალირდება
3. ბრაუზერის DevTools-ში (F12) 2 ახალი tab გამოჩნდება: **Components** და **Profiler**

### 1.2 აპლიკაციის გახსნა

1. გაუშვით სერვერი (წინაპირობაში აღწერილი ბრძანებით)
2. გახსენით `http://localhost:5173` (Vite-ის default პორტი)
3. DevTools გახსენით: **Cmd+Option+I** (Mac) ან **Ctrl+Shift+I** (Windows/Linux)
4. **Components** tab უნდა გააქტიურდეს (ლურჯი React-ის ლოგო)

> **რას ამატებს React DevTools?** ჩვეულებრივი DevTools-ით (Elements, Console) მხოლოდ HTML-ს და JavaScript-ს ხედავთ. React DevTools კი გაჩვენებთ **React-ის შიდა სტრუქტურას** — კომპონენტების ხეს, props-ებს, state-ს, hooks-ებს, და თითოეული კომპონენტის რენდერის მიზეზს. ეს არის განსხვავება "HTML-ის ნახვასა" და "React-ის გაგებას" შორის.

## ეტაპი 2: Components Tab — კომპონენტების ხე

### 2.1 კომპონენტების იერარქიის ნახვა

გახსენით **Components** tab. მარცხენა პანელში დაინახავთ კომპონენტთა ხეს:

```
App
├── SearchBar
├── ProductList
│   ├── ProductCard (ლეპტოპი)
│   ├── ProductCard (ტელეფონი)
│   ├── ProductCard (ყურსასმენი)
│   ├── ProductCard (მაუსი)
│   ├── ProductCard (კლავიატურა)
│   ├── ProductCard (მონიტორი)
│   ├── ProductCard (ვებკამერა)
│   ├── ProductCard (პლანშეტი)
│   ├── ProductCard (დამტენი)
│   └── ProductCard (სმარტ საათი)
└── CartSummary
```

ეს არის React-ის "ნამდვილი" სტრუქტურა — არა HTML-ის `<div>`-ები, არამედ თქვენი კომპონენტები სახელებით.

### 2.2 Props და State-ის ინსპექტირება

1. დააჭირეთ **App** კომპონენტს ხეში
2. მარჯვენა პანელში დაინახავთ:
   - **hooks** → `State`: products მასივი (10 ობიექტი)
   - **hooks** → `State`: searchTerm (ცარიელი string)
   - **hooks** → `State`: cartItems (ცარიელი მასივი)

3. დააჭირეთ **ProductCard**-ს (მაგ., „ლეპტოპი")
4. მარჯვენა პანელში ნახავთ:
   - **props** → `product`: `{ id: 1, name: "ლეპტოპი", price: 2499, inStock: true, ... }`
   - **props** → `onAddToCart`: ფუნქცია

### 2.3 Hooks-ის ნახვა

1. დააჭირეთ **SearchBar** კომპონენტს
2. მარჯვენა პანელში **hooks** სექციაში ნახავთ:
   - `Ref`: `{ current: 1 }` — ეს არის `useRef`-ით შექმნილი render counter

> **რატომ hooks და არა state/props ცალკე?** React DevTools-ის ახალი ვერსია ყველა hook-ს ერთად აჩვენებს hooks სექციაში — `useState`, `useRef`, `useEffect`, `useMemo` და სხვა. ეს გეხმარებათ სრული სურათის დანახვაში.

## ეტაპი 3: State-ის ცოცხალი რედაქტირება

### 3.1 State-ის შეცვლა DevTools-იდან

1. **Components** tab-ზე დააჭირეთ **App** კომპონენტს
2. მარჯვენა პანელში იპოვეთ `State` → `searchTerm` (ცარიელი string)
3. **დააჭირეთ მნიშვნელობას** და ჩაწერეთ: `"ტელ"`
4. UI მაშინვე განახლდება — მხოლოდ „ტელეფონი" გამოჩნდება პროდუქტების სიაში!

ეს არის ცოცხალი რედაქტირება — კოდის შეცვლის გარეშე, პირდაპირ DevTools-იდან მანიპულირებთ აპლიკაციის მდგომარეობას.

### 3.2 Cart-ის State-ის რედაქტირება

1. ჯერ დაამატეთ რამდენიმე პროდუქტი კალათაში (UI-დან, ღილაკით)
2. **App** კომპონენტში იპოვეთ `State` → `cartItems` მასივი
3. გააფართოეთ მასივი → გააფართოეთ ერთ-ერთი ობიექტი
4. შეცვალეთ `quantity` მნიშვნელობა (მაგ., 1 → 5)
5. კალათაში მაშინვე აისახება ახალი რაოდენობა და ფასი!

### 3.3 Props-ის რედაქტირება

1. დააჭირეთ ნებისმიერ **ProductCard** კომპონენტს
2. მარჯვენა პანელში `props` → `product` → `price` მნიშვნელობას შეცვალეთ (მაგ., 2499 → 99)
3. UI-ში ამ კარტის ფასი მაშინვე შეიცვლება

> **სად არის ეს სასარგებლო?** ტესტირებისას — არ გჭირდებათ კოდში მონაცემების ცვლილება, refresh, ხელახალი მოქმედებები. შეგიძლიათ სწრაფად შეამოწმოთ, როგორ გამოიყურება UI სხვადასხვა მონაცემებით.

## ეტაპი 4: Highlight Updates — რენდერინგის ვიზუალიზაცია

### 4.1 ჩართვა

1. **Components** tab-ზე დააჭირეთ **Settings** (გადაცემათა კოლოფის ხატულა) ზედა მარჯვენა კუთხეში

ახლა აკრიფეთ ძიების ველში რამდენიმე ასო. **ყურადღებით დააკვირდით:**

თითოეულ ასოზე **ყველა კომპონენტი** მწვანედ მოციმციმდება:
- SearchBar — ეს ლოგიკურია (მისი input იცვლება)
- ProductList — ესეც გასაგებია (ფილტრირებული სია იცვლება)
- **ყოველი ProductCard** — მათ შორის ისინიც, რომლებიც არ გაფილტრულა!
- **CartSummary** — კალათა საერთოდ არ შეცვლილა, მაგრამ მაინც რენდერდება!

### 4.3 ტესტირება — კალათაში დამატება

დააჭირეთ ნებისმიერ პროდუქტს „კალათაში დამატება":

- **SearchBar** — საძიებო ველი არ შეცვლილა, მაგრამ მაინც რენდერდება!
- **ყოველი ProductCard** — არცერთი პროდუქტი არ შეცვლილა, მაგრამ ყველა რენდერდება!

> **რატომ ხდება ეს?** React-ში default ქცევა ასეთია: როცა მშობელი კომპონენტი (App) ხელახლა რენდერდება (state ცვლილების გამო), **ყველა შვილი კომპონენტიც** ხელახლა რენდერდება — იმის მიუხედავად, შეიცვალა მათი props თუ არა. ეს არის "wasteful re-rendering" — ზედმეტი რენდერინგი, რომელიც ამცირებს წარმადობას. გამოსავალი არის `React.memo`, `useMemo` და `useCallback` — ამას შემდეგ ლექციაში ვისწავლით.

## ეტაპი 6: "Why did this render?" — რენდერის მიზეზი

### 6.1 ჩართვა

1. **Profiler** tab-ზე დააჭირეთ **Settings** (გადაცემათა კოლოფის ხატულა)
2. მონიშნეთ: **"Record why each component rendered while profiling"**
3. დახურეთ Settings

### 6.2 ახალი ჩაწერა

1. დააჭირეთ **Record**
2. აკრიფეთ ძიების ველში ერთი ასო (მაგ., `"ლ"`)
3. დააჭირეთ **Stop**

### 6.3 მიზეზის ანალიზი

Flamegraph-ში დააჭირეთ სხვადასხვა კომპონენტს. მარჯვენა პანელში ნახავთ **"Why did this render?"** სექციას:

- **SearchBar** → "Props changed" — ლოგიკურია, `searchTerm` prop შეიცვალა
- **ProductList** → "Props changed" — ფილტრირებული მასივი შეიცვალა
- **ProductCard** (რომელიც სიაში დარჩა) → "Props changed" ან "The parent component rendered"
- **CartSummary** → **"Props changed: (onRemoveFromCart, onClearCart)"**

> **შენიშვნა:** გაფილტრული ProductCard-ები (რომლებიც სიაში აღარ ჩანს) Profiler-ში საერთოდ არ გამოჩნდება — ისინი **unmount** გახდა, ანუ React-ის ხიდან ამოიღო. Profiler-ში მხოლოდ დარენდერებული კომპონენტები ჩანს.

შედეგი:

- **SearchBar** — მიზეზი: Props changed — ლეგიტიმურია: დიახ
- **ProductList** — მიზეზი: Props changed — ლეგიტიმურია: დიახ
- **ProductCard (დარჩენილი)** — მიზეზი: Props changed / Parent rendered — ლეგიტიმურია: **არა — ზედმეტი!**
- **CartSummary** — მიზეზი: **Props changed** (App ყოველ რენდერზე ახალ ფუნქციებს ქმნის) — ლეგიტიმურია: **არა — ზედმეტი! `useCallback`-ით მოგვარდება**

> **"The parent component rendered"** — ეს არის React-ის ყველაზე გავრცელებული წარმადობის პრობლემის მიზეზი. კომპონენტი ხელახლა რენდერდება არა იმიტომ, რომ მისი მონაცემები შეიცვალა, არამედ იმიტომ, რომ მშობელი კომპონენტი ხელახლა დარენდერდა. სწორედ ამიტომ არსებობს:
> - `React.memo()` — კომპონენტს ამახსოვრებს და props-ის შეუცვლელობისას არ რენდერს
> - `useMemo()` — გამოთვლის შედეგს ამახსოვრებს
> - `useCallback()` — ფუნქციის რეფერენსს ამახსოვრებს
>
> ეს ოპტიმიზაციები შემდეგ ლექციაში განვიხილავთ.

## ეტაპი 7: Render Counter-ების დაკვირვება

### 7.1 ჩაშენებული მთვლელები

ჩვენს აპლიკაციაში ყოველ კომპონენტს აქვს ყვითელი **render badge** — ის `useRef`-ით ითვლის, რამდენჯერ დარენდერდა კომპონენტი.

სცადეთ:
1. გახსნისას ყველა badge აჩვენებს `renders: 1`
2. აკრიფეთ ძიების ველში 5 ასო
3. ყველა ProductCard-ის badge აჩვენებს `renders: 6` (1 საწყისი + 5 ასო)
4. CartSummary-ც აჩვენებს `renders: 6` — თუმცა კალათა არ შეცვლილა!

### 7.2 რატომ useRef და არა useState?

```javascript
const renderCount = useRef(0);
renderCount.current++;
```

`useRef` არ იწვევს ხელახალ რენდერს მნიშვნელობის ცვლილებისას. თუ `useState`-ს გამოვიყენებდით counter-ისთვის, ის თავადაც გამოიწვევდა ახალ რენდერს — უსასრულო ციკლი!

## ეტაპი 8: VS Code Debugger — პრაქტიკული გამოყენება

### 8.1 launch.json — კონფიგურაცია

VS Code-ს შეუძლია Chrome ბრაუზერთან დაკავშირება და JavaScript-ის debug პირდაპირ IDE-ში. პროექტში `.vscode/launch.json` უკვე შექმნილია:

```
demo-react-devtools/
├── .vscode/
│   └── launch.json    ← კონფიგურაცია
├── src/
└── ...
```

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "chrome",
      "request": "launch",
      "name": "Launch Chrome",
      "url": "http://localhost:5173",
      "webRoot": "${workspaceFolder}"
    }
  ]
}
```

### 8.2 Debug-ის გაშვება

1. ტერმინალში გაუშვით: `npm run dev` (Vite dev server)
2. VS Code-ში დააჭირეთ **F5** (ან Run → Start Debugging)
3. Chrome გაიხსნება `localhost:5173`-ზე — VS Code-თან დაკავშირებული

> **Mac-ზე:** თუ F5/F10/F11 სისტემურ ფუნქციებს ასრულებს (ხმა, სიკაშკაშე), გამოიყენეთ **Fn+F5**, **Fn+F10** და ა.შ. ან System Settings → Keyboard → ჩართეთ "Use F1, F2, etc. keys as standard function keys".

### 8.3 პრაქტიკა — handleAddToCart-ის debug

**დავალება:** კალათაში უკვე არსებული პროდუქტის ხელახლა დამატებისას რაოდენობა იზრდება. გავიაროთ ეს ლოგიკა VS Code debugger-ით.

#### ნაბიჯი 1 — Breakpoint-ის დასმა

VS Code-ში გახსენით `src/App.jsx`. იპოვეთ `handleAddToCart` ფუნქცია (ხაზი ~49). დააჭირეთ ხაზის ნომრის მარცხნივ (gutter-ზე) — **წითელი წრე** გაჩნდება. Breakpoint დასვით `setCart(prevCart => {` ხაზზე.

#### ნაბიჯი 2 — მოქმედების გამეორება

1. ბრაუზერში დაამატეთ **ლეპტოპი** კალათაში (პირველად)
2. VS Code-ში კოდი **შეჩერდება** breakpoint-ზე — ხაზი ყვითლად გამოიკვეთება
3. მარცხენა sidebar-ში (Run and Debug) ნახავთ:

**VARIABLES** პანელი (= Chrome-ის Scope):
```
Local:
  product: {id: 1, name: "ლეპტოპი", price: 2499, ...}
  prevCart: []    ← კალათა ცარიელია
```

4. დააჭირეთ **F10** (Step Over) — `find()` შესრულდება
5. VARIABLES-ში ნახავთ: `existing: undefined` — პროდუქტი ჯერ კალათაში არ არის
6. **F10** კიდევ — `if (existing)` გამოტოვდება, `return [...prevCart, {...}]` შესრულდება
7. დააჭირეთ **F5** (Continue) — აპლიკაცია გააგრძელებს, ლეპტოპი კალათაშია

#### ნაბიჯი 3 — იგივე პროდუქტის ხელახლა დამატება

1. ბრაუზერში კვლავ დააჭირეთ ლეპტოპის **"კალათაში დამატება"**
2. კოდი ისევ შეჩერდება. ახლა VARIABLES-ში:

```
Local:
  product: {id: 1, name: "ლეპტოპი", price: 2499, ...}
  prevCart: [{id: 1, name: "ლეპტოპი", quantity: 1, ...}]    ← უკვე არის!
```

3. **F10** — `existing: {id: 1, name: "ლეპტოპი", quantity: 1, ...}` — იპოვა!
4. **F10** — `if (existing)` → true, შედის `return prevCart.map(...)` ბლოკში
5. **F10** — `quantity: item.quantity + 1` → **2** გახდება

> **Watch და Debug Console** — იგივე კონცეფციაა, რაც Chrome DevTools-ში (ეტაპი 6 და 8). VS Code-ში WATCH პანელი მარცხენა sidebar-შია, Debug Console კი ქვემოთ (Cmd+Shift+Y). ფუნქციურად იდენტურია Chrome-ის Watch-ისა და Console-ის.

1. **React DevTools არის React დეველოპერის უმთავრესი ინსტრუმენტი** — ის აჩვენებს იმას, რასაც ჩვეულებრივი DevTools ვერ ხედავს: კომპონენტთა ხეს, state-ს, props-ებს და hooks-ებს.

3. **Profiler-ის Flamegraph** აჩვენებს თითოეული კომპონენტის render დროს — განიერი ზოლი ნიშნავს მეტ დროს, ნაცრისფერი ნიშნავს „არ ირენდერა".

4. **"Why did this render?"** პასუხობს სამ შეკითხვას:

   - State შეიცვალა?
   - მშობელი კომპონენტი დარენდერდა? (ყველაზე ხშირი „ზედმეტი" მიზეზი)

5. **შემდეგ ლექციაში** ვისწავლით ამ პრობლემების გადაჭრას — `React.memo`, `useMemo`, `useCallback` ოპტიმიზაციებს, რომლებიც ზედმეტ რენდერებს აღმოფხვრის.
