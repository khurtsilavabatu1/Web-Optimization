# დავალება: Memory Leaks და Error Boundaries — Live Ops Console

**ლექცია:** კვირა 4, ლექცია 3
**პროექტი:** `homework-memory-errors/`
**შესრულების დრო:** ~2-3 საათი (დამოუკიდებლად)

---

## აღწერა

მოცემულია **Live Ops Console** — React აპლიკაცია სერვერების მონიტორინგისთვის: ცალ-ცალკე
ჩართვადი ვიჯეტები (ტაიმერი, resize, ლაივ ლოგი, გრაფიკი) და ინციდენტების პანელი.
აპი გარეგნულად მუშაობს, მაგრამ შიგნით **5 memory leak-ი + 1 გატეხილი Error Boundary-ა** —
იგივე ტიპის, რაც ლექციის გაიდში (`../GUIDE.md`) `demo-memory-leaks`-ზე განვიხილეთ,
ოღონდ **სხვა დომენში და სხვა კოდში**.

განსხვავება ლექციის პროექტისგან:

- აქ **„გამოსწორების გზა" ბლოკები არ არის** — გამოსწორება თქვენი ამოცანაა
- კოდში `// BUG #N` კომენტარები **არ არის**
- გვერდის ბოლოს პანელი მხოლოდ **სიმპტომს** და გამეორების ნაბიჯებს აღწერს
- თითოეული პრობლემისთვის **სავალდებულოა კონკრეტული ინსტრუმენტის გამოყენება**

**შენი ამოცანა:** იპოვე 5-ვე leak-ი მითითებული ინსტრუმენტით, გამოასწორე, **რიცხვებით**
დაადასტურე (before/after: Event Listeners, JS Heap, DOM Nodes) და გამოასწორე Error Boundary.

> ⚠️ **მთავარი წესი:** leak-ი „თვალით" კოდის კითხვით რომ იპოვო, ეს დავალება არ ითვლება
> შესრულებულად. ყოველ პრობლემაზე უნდა აჩვენო **გაზომვა** (Performance Monitor / Heap Snapshot
> / Console) გასწორებამდე და მის შემდეგ.

cd ~/Desktop/Web-optimization/კვირა-4/ლექცია-3-memory-leaks-და-error-boundaries/დავალება/homework-memory-errors

**JS event listeners**.

- [ ] დაადასტურეთ: „💥 render-ის შეცდომა" → fallback ჩანს (თეთრი ეკრანი აღარ არის) →
      „ხელახლა ცდა" → კონსოლი ისევ მუშაობს

      გრაფიკი", შემდეგ გამოიწვიეთ render-ის შეცდომა. ჩაწერეთ, რა დაემართა დანარჩენ
