## აღწერა

მოცემულია **Order Desk** — React აპლიკაცია შეკვეთების დასამუშავებლად: შეკვეთების სია,
დეტალები, კუპონი და გადასახდელის გამოთვლა. აპი გარეგნულად მუშაობს, მაგრამ შიგნით
**5 ბაგია** — ყველა ლექციის „გავრცელებული React შეცდომების" სიიდან (`../კონსპექტი.md`, 4.2).

განსხვავება ლექციის პროექტისგან: `demo-source-maps`-ზე ერთი შეცდომით ვნახეთ, **როგორ**
მუშაობს source maps. აქ თქვენ ამ ინსტრუმენტს **სამუშაო პროცესად** აქცევთ:

1. ჯერ ნახავთ, **რას ხედავს რეალური მომხმარებელი** (production build, source maps გამორთული)
2. შემდეგ ჩართავთ source maps-ს და იმავე შეცდომას **ორიგინალ კოდში** იპოვით
3. გამოასწორებთ და ბოლოს დააყენებთ **უსაფრთხო** production კონფიგურაციას (`'hidden'`)

> ⚠️ **მთავარი წესი:** ბაგი პირდაპირ dev რეჟიმში რომ იპოვო და გამოასწორო, ეს დავალება
> არ ითვლება შესრულებულად. ყოველ ბაგზე უნდა ჩაწერო **ორივე** სურათი: production build-ის
> stack trace source maps-ის გარეშე და მასთან ერთად.

## წინაპირობა

```bash
cd ~/Desktop/Web-optimization/კვირა-4/ლექცია-4-source-maps/დავალება/homework-source-maps
npm install
```

ორი რეჟიმი, რომელსაც მონაცვლეობით გამოიყენებთ:

```bash
npm run dev        # dev სერვერი — სრული warning-ები, source maps ავტომატურად
npm run build      # production ბილდი → dist/
npm run preview    # dist/-ის ჰოსტინგი — „ისე, როგორც სერვერზე"
```

> გადაიკითხეთ `../GUIDE.md`: ეტაპი 2 (dev vs production build), 3 (source maps-ის ჩართვა),
> 4-5 (რას ხსნის source maps, .map ფაილის სტრუქტურა), 6 (Vite-ის კონფიგურაცია),
> 8 (`hidden-source-map` და უსაფრთხოება), 9 (გავრცელებული React შეცდომები).

**ტერმინალის სასარგებლო ბრძანებები:**

```bash
rm -rf dist && npm run build          # სუფთა ბილდი
ls -lh dist/assets/                   # ფაილების ზომები
tail -c 200 dist/assets/index-*.js    # sourceMappingURL კომენტარის შემოწმება
du -sh dist                           # მთელი ბილდის ზომა
```
