# ლექცია 4 — Source Maps + შეჯამება და პრაქტიკა

## 4.1 Source Maps

### რა არის?
Source Maps აკავშირებს minified/bundled კოდს ორიგინალ source code-თან — production-ში debug-ი ორიგინალ კოდზე.

```javascript
// Minified (bundle.js):
function a(b,c){return b+c}

// Source Map (bundle.js.map):
// a → calculateSum, b → firstNumber, c → secondNumber
// ფაილი: src/math.js, ხაზი: 5
```

### Dev build vs Production build

| | `npm run dev` | `npm run build` |
|---|---|---|
| Bundling | არ ხდება — native ES modules | ერთიანი bundle, tree-shaken |
| Minification | არა | კი (terser/esbuild) |
| Source maps | ავტომატურად ჩართული | მხოლოდ თუ ჩართავთ |
| React | development build — სრული warning-ები | production build — warning-ები ამოჭრილია |
| Rebuild | HMR, მყისიერი | სრული build, წამები |
| შედეგი | მეხსიერებაში | `dist/` ფოლდერი |

- **dev რეჟიმი** დეველოპერის სიჩქარეზეა ოპტიმიზებული, **production build** — მომხმარებლის სიჩქარეზე.
- **„ლოკალური ბილდი" ≠ „dev რეჟიმი":** `npm run build && npm run preview` ლოკალურად იმავე მინიფიცირებულ არტეფაქტს აგდებს, რაც სერვერზე წავა. ლოკალურ და რეალურ production ბილდს შორის განსხვავება ჩვეულებრივ მხოლოდ გარემოს ცვლადები (`.env.production`), CI/CD ნაბიჯები (Sentry upload, CDN deploy) და `base` path-ია.
- **სწორედ აქედან იბადება source maps-ის საჭიროება** — production build წაუკითხავია, stack trace უსარგებლო.

### კონფიგურაცია:
```javascript
// Vite
export default {
  build: {
    sourcemap: true,          // .map ფაილები
    // sourcemap: 'hidden',   // .map ფაილები, reference გარეშე
  },
};

// Webpack
module.exports = {
  devtool: 'source-map',           // production
  // devtool: 'eval-source-map',   // development (სწრაფი)
};
```

### უსაფრთხოება:
- **არ გაუზიარეთ source maps საჯარო სერვერს!**
- გამოიყენეთ `hidden-source-map` — Sentry-ს ცალკე ატვირთეთ

## 4.2 გავრცელებული React შეცდომები — სწრაფი reference

```
"Cannot read properties of undefined"
→ data ჯერ არ ჩატვირთულა. გამოსწორება: optional chaining ან loading state

"Objects are not valid as a React child"
→ ობიექტის პირდაპირ render. გამოსწორება: obj.propertyName

"Each child in a list should have a unique key prop"
→ .map()-ში key არ არის. გამოსწორება: <li key={item.id}>

"Too many re-renders"
→ setState render-ის დროს (infinite loop). გამოსწორება: event handler ან useEffect

"Cannot update a component while rendering a different component"
→ სხვა კომპონენტის state-ის ცვლილება render-ში. გამოსწორება: useEffect
```
